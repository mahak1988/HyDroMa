# 2. اصول بنیادین Responsive Design

## 2.1. Content First

چیدمان باید بر اساس اولویت محتوا طراحی شود، نه بر اساس اندازه یک دستگاه خاص.

## 2.2. Mobile First

برای تجربه‌هایی که ماهیت عمومی یا مصرف‌کننده دارند، طراحی از کوچک‌ترین عرض کاربردی آغاز شود.

برای ابزارهای تخصصی مانند نقشه‌های تحلیلی و شبیه‌سازی، طراحی باید هم‌زمان نیازهای محیط دسکتاپ را نیز در نظر بگیرد.

Mobile First به معنی حذف قابلیت‌های تخصصی از موبایل یا محدود کردن تمام محصولات به الگوی یکسان نیست.

## 2.3. Progressive Enhancement

قابلیت‌های پایه باید در شرایط محدود نیز قابل استفاده باشند و قابلیت‌های پیشرفته بر اساس توان دستگاه و محیط فعال شوند.

## 2.4. Adaptive Experience

در صورت نیاز، ساختار تجربه می‌تواند با نوع دستگاه تغییر کند؛ نه اینکه صرفاً اندازه عناصر کوچک شود.

## 2.5. Performance Awareness

طراحی باید هزینه پردازش، حافظه، شبکه و مصرف انرژی را در نظر بگیرد.

## 2.6. Functional Continuity

کاربر باید بتواند در صورت پشتیبانی محصول، فعالیت خود را میان دستگاه‌ها ادامه دهد.

# 4. Breakpoint Architecture

Breakpointها باید بر اساس شکستن طبیعی Layout تعیین شوند، نه صرفاً نام دستگاه‌ها.

مقادیر زیر نقطه شروع پیشنهادی هستند و نهایی نیستند.

| شناسه | عرض viewport | کاربرد |
|---|---:|---|
| BP-01 | کمتر از 360px | نمایشگر بسیار کوچک |
| BP-02 | 360–479px | موبایل کوچک |
| BP-03 | 480–767px | موبایل بزرگ |
| BP-04 | 768–1023px | تبلت |
| BP-05 | 1024–1279px | لپ‌تاپ کوچک |
| BP-06 | 1280–1535px | دسکتاپ |
| BP-07 | 1536px به بالا | نمایشگر بزرگ |

قواعد:

- Breakpoint نباید بدون دلیل افزایش یابد.
- Layout باید در عرض‌های بین Breakpointها نیز پایدار باشد.
- محتوای طولانی نباید باعث Overflow ناخواسته شود.
- نقاط شکست باید با آزمون واقعی اصلاح شوند.

# 5. Grid System

## 5.1. ساختار پیشنهادی

سیستم Grid می‌تواند بر پایه 12 ستون در نمایشگرهای بزرگ و ساختارهای ساده‌تر در موبایل باشد.

پیشنهاد اولیه:

| دستگاه | ستون |
|---|---:|
| موبایل | 4 |
| تبلت | 8 |
| دسکتاپ | 12 |
| نمایشگر بزرگ | 12 یا 16 |

تعداد ستون‌ها باید متناسب با ساختار صفحه باشد.

## 5.2. Container

عرض محتوا باید محدود شود تا خوانایی در نمایشگرهای بزرگ حفظ شود.

برای صفحات تحلیلی می‌توان از Containerهای گسترده‌تر استفاده کرد.

## 5.3. Gutter

فاصله ستون‌ها باید با نظام فاصله‌گذاری Design System هماهنگ باشد.

## 5.4. RTL/LTR

Grid باید مستقل از جهت متن عمل کند و از ویژگی‌های منطقی CSS استفاده کند.

# 6. Responsive Typography

اندازه متن باید در نمایشگرهای مختلف خوانا باقی بماند.

## 6.1. اصول

- استفاده از مقیاس تایپوگرافی مشخص.
- کنترل طول خط.
- جلوگیری از کوچک شدن بیش از حد متن.
- حفظ سلسله‌مراتب عنوان‌ها.
- پشتیبانی از فارسی و انگلیسی.
- بررسی متن‌های ترکیبی.

## 6.2. Fluid Typography

استفاده از `clamp()` می‌تواند برای اندازه‌های سیال مناسب باشد.

نمونه:

```css
.page-title {
  font-size: clamp(1.75rem, 3vw, 3rem);
}
```

این نمونه صرفاً الگوی فنی است و مقادیر نهایی باید با فونت و Design System مصوب تطبیق یابند.

## 6.3. Line Length

طول خط باید با نوع محتوا سازگار باشد.

متن علمی طولانی، متن عمومی و برچسب‌های رابط نباید از یک قاعده یکسان پیروی کنند.

# 31. معیار پذیرش

یک صفحه زمانی از نظر Responsive آماده پذیرش است که:

- در عرض‌های هدف Overflow ناخواسته نداشته باشد.
- متن‌ها خوانا باشند.
- عملیات اصلی قابل دسترس باشند.
- اهداف لمسی مناسب باشند.
- فرم‌ها قابل استفاده باشند.
- نمودارها اطلاعات ضروری را حفظ کنند.
- نقشه در اندازه‌های مختلف قابل تعامل باشد.
- RTL/LTR درست کار کند.
- وضعیت‌های شبکه روشن باشند.
- عملکرد روی دستگاه‌های ضعیف بررسی شده باشد.
- دسترس‌پذیری بررسی شده باشد.
- آزمون‌های لازم مستند باشند.

# 34. معیار موفقیت نهایی

نظام Responsive زمانی موفق است که:

- سه برند در دستگاه‌های مختلف تجربه منسجم داشته باشند.
- کاربران بتوانند وظایف اصلی خود را در موبایل و دسکتاپ انجام دهند.
- ابزارهای علمی در نمایشگرهای کوچک نیز قابل استفاده باشند.
- کاربران دستگاه‌های ضعیف از خدمات پایه محروم نشوند.
- عملکرد در اینترنت محدود قابل قبول باشد.
- داده‌های علمی در تغییر چیدمان تحریف نشوند.
- تجربه RTL/LTR در تمام اندازه‌ها پایدار باشد.
- دسترس‌پذیری حفظ شود.
- توسعه آینده به بازطراحی بنیادی چیدمان وابسته نباشد.
