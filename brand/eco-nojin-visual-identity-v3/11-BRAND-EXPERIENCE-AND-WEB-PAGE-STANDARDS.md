# 1. هدف سند

این سند مشخص می‌کند هویت بصری Eco Nojin چگونه باید در تجربه واقعی وب و محصولات دیجیتال نمود پیدا کند.

# 3. اصول مشترک تجربه کاربری

تمام صفحات باید از اصول زیر پیروی کنند.

## 3.1 Clarity First

کاربر باید در چند ثانیه متوجه شود:

- در کدام بخش قرار دارد.
- این بخش چه کاری انجام می‌دهد.
- چه اطلاعاتی دریافت می‌کند.
- چه اقدامی می‌تواند انجام دهد.

## 3.2 Visual Hierarchy

هر صفحه باید دارای سلسله‌مراتب مشخص باشد:

1. عنوان اصلی
2. توضیح یا پیام کلیدی
3. محتوای اصلی
4. اقدام اصلی
5. محتوای تکمیلی

## 3.3 Consistency

رنگ‌ها، فونت‌ها، فاصله‌ها، کامپوننت‌ها و الگوهای تعاملی باید با Design System مصوب سازگار باشند.

## 3.4 Purposeful Design

هیچ عنصر بصری صرفاً برای تزئین نباید اضافه شود.

هر تصویر، خط، نمودار، آیکون، انیمیشن یا فضای خالی باید هدف مشخصی داشته باشد.

## 3.5 Progressive Disclosure

اطلاعات پیچیده باید به‌صورت مرحله‌ای ارائه شوند.

در صفحات علمی، اطلاعات تخصصی نباید بدون ضرورت در برابر کاربران عمومی قرار گیرند.

## 3.6 Accessibility

دسترسی‌پذیری باید از ابتدای طراحی لحاظ شود، نه اینکه در پایان به‌صورت اصلاح ظاهری اضافه شود.

# 9. زبان بصری و کاربرد رنگ

## 9.1 اصل کلی

پس‌زمینه عمومی صفحات باید روشن، زنده و خوانا باشد.

زمینه تیره نباید به‌عنوان پیش‌فرض کل محصول انتخاب شود.

## 9.2 نقش رنگ

رنگ باید برای انتقال معنا استفاده شود:

- Primary Brand
- Secondary Brand
- Accent
- Success
- Warning
- Error
- Information
- Neutral

## 9.3 تفکیک سه برند

رنگ‌های هر برند باید پس از انتخاب و تصویب پالت نهایی تعیین شوند.

تا قبل از آن:

- هیچ رنگی مصوب نیست.
- هیچ Theme نهایی نیست.
- هیچ رنگ آزمایشی نباید در محصول رسمی تثبیت شود.

## 9.4 رنگ داده

رنگ نمودارها و نقشه‌ها باید مستقل از رنگ تزئینی برند، از نظر خوانایی و معنا بررسی شوند.

# 11. RTL و LTR

پشتیبانی از چندزبانگی باید در معماری طراحی لحاظ شود.

## 11.1 فارسی و عربی

- جهت پایه RTL
- ترتیب منطقی عناصر متناسب با زبان
- تراز صحیح متن
- کنترل مناسب فرم‌ها
- پشتیبانی از متن‌های ترکیبی

## 11.2 انگلیسی

- جهت پایه LTR
- ناوبری و ترتیب اجزا متناسب با زبان
- نمایش صحیح نمودارها و جدول‌ها

## 11.3 اصل فنی

جهت متن نباید با جابه‌جایی دستی و موردی اجزا شبیه‌سازی شود.

استفاده از ویژگی‌های منطقی CSS و معماری سازگار با RTL/LTR توصیه می‌شود.

- انیمیشن نباید جایگزین بازخورد متنی شود.
- عملکرد در دستگاه‌های ضعیف بررسی شود.

## 15.3 Desktop

- استفاده مؤثر از فضای گسترده
- امکان نمایش چند پنل
- حفظ خوانایی
- کنترل تراکم اطلاعات

## 15.4 اصل مهم

Responsive Design نباید صرفاً به کوچک کردن عناصر دسکتاپ محدود شود.

ساختار و اولویت محتوا باید متناسب با نوع دستگاه بازآرایی شوند.

# 16. وضعیت‌های استاندارد رابط کاربری

تمام کامپوننت‌های تعاملی باید وضعیت‌های مناسب داشته باشند.

| وضعیت | کاربرد |
|---|---|
| Default | حالت عادی |
| Hover | اشاره‌گر |
| Focus | تمرکز صفحه‌کلید |
| Active | تعامل فعال |
| Disabled | غیرفعال |
| Loading | پردازش |
| Success | موفقیت |
| Warning | هشدار |
| Error | خطا |
| Empty | داده خالی |

خطای دریافت داده نباید به‌عنوان مقدار واقعی نمایش داده شود.

# 17. عملکرد و کیفیت تجربه

طراحی باید با محدودیت‌های عملکردی وب سازگار باشد.

موارد بررسی:

- زمان بارگذاری
- حجم تصاویر
- بارگذاری فونت
- تعداد درخواست‌ها
- رندر نمودارها
- تعامل نقشه
- عملکرد موبایل
- مصرف حافظه
- پایداری رابط

در صورت استفاده از داده‌های سنگین مکانی یا علمی، بارگذاری تدریجی و مدیریت منابع باید در نظر گرفته شود.

# 18. دسترس‌پذیری

هدف طراحی، انطباق با WCAG 2.2 AA است.

موارد الزامی:

- کنتراست مناسب
- Focus Visible
- ناوبری با صفحه‌کلید
- Label برای فرم‌ها
- پیام خطای قابل فهم
- متن جایگزین تصاویر
- ساختار معنایی HTML
- عدم وابستگی معنا به رنگ
- پشتیبانی از بزرگ‌نمایی
- کنترل انیمیشن

انطباق تنها با بررسی ظاهری قابل تأیید نیست و باید آزمون واقعی انجام شود.

# 19. استاندارد محتوای صفحات

محتوا باید:

- روشن و دقیق باشد.
- با مخاطب هدف متناسب باشد.
- از ادعاهای اثبات‌نشده پرهیز کند.
- اصطلاحات علمی را درست به کار ببرد.
- اطلاعات عملیاتی را از محتوای تبلیغاتی جدا کند.
- در زبان‌های مختلف معنای یکسان داشته باشد.

در صفحات علمی، تفکیک مشاهده، برآورد، پیش‌بینی و شبیه‌سازی الزامی است.
