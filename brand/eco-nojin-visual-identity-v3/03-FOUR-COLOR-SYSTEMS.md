# 1. هدف سند

این سند چهار نظام رنگی مستقل را برای هویت بصری اکوسیستم Eco Nojin تعریف می‌کند.

هر نظام رنگی باید بتواند به‌تنهایی شخصیت یک برند بین‌المللی را شکل دهد و در عین حال در سه زیرمجموعه اصلی اکوسیستم قابل استفاده باشد:

1. **Eco Nojin:** برند مادر و هویت اصلی اکوسیستم.
2. **HyDroMA:** موتور علمی، محاسباتی و هوشمند.
3. **Nojin Marketplace:** بازارگاه اقتصادی، تجاری، گردشگری و اجتماعی.

چهار نظام رنگی باید از نظر شخصیت، ترکیب رنگ، شدت بصری و احساس منتقل‌شده واقعاً متفاوت باشند؛ نه اینکه صرفاً تغییر جزئی در یک پالت مشترک باشند.

هیچ‌یک از رنگ‌ها یا نظام‌های این سند تأیید نهایی نشده‌اند.

## 1.1 هدف طراحی

هویت رنگی نهایی باید هم‌زمان این ویژگی‌ها را منتقل کند:

- قدرت و اعتبار بین‌المللی
- سرزندگی و انرژی
- طبیعت و حیات
- گرما و صمیمیت
- نوآوری و فناوری
- اعتماد و ثبات
- امید و آینده‌نگری
- تمایز بصری و قابلیت تشخیص

## 1.2 خروجی مورد انتظار

برای هر چهار نظام رنگی باید موارد زیر قابل ارزیابی باشد:

- رنگ‌های اصلی برند
- رنگ‌های ثانویه
- رنگ‌های تأکیدی
- رنگ‌های طبیعت و سرزمین
- رنگ‌های علمی و فناوری
- رنگ‌های تجاری و بازارگاه
- رنگ‌های پس‌زمینه و سطوح
- رنگ‌های متن
- رنگ‌های مرزی و خطوط
- رنگ‌های وضعیت و هشدار
- رنگ‌های نمودار و داده
- قواعد استفاده در سه برند
- ترکیب‌های مجاز رنگ و پس‌زمینه
- قابلیت استفاده در رابط کاربری روشن
- خوانایی و دسترس‌پذیری
- عملکرد در صفحات واقعی و داشبوردهای پیچیده

# 2. اصول غیرقابل‌مذاکره طراحی رنگ

## 2.1 پس‌زمینه روشن

رابط عمومی Eco Nojin باید روشن، زنده و خوش‌خوان باشد.

رنگ‌های زیر نباید پس‌زمینه غالب صفحات عمومی باشند:

- مشکی
- سرمه‌ای بسیار تیره
- ذغالی
- سبز بسیار تیره
- خاکستری سنگین

استفاده محدود از رنگ‌های عمیق برای هدرهای کوچک، بخش‌های ویژه، نمودارها، نوارهای تأکیدی یا عناصر خاص مجاز است.

## 2.2 رنگ‌های زنده و قدرتمند

پالت نهایی نباید بی‌روح، کم‌رمق یا بیش از حد خاکی و خاموش باشد.

رنگ‌ها باید انرژی بصری داشته باشند، اما نباید به رنگ‌های نئونی، کودکانه یا بیش از حد اشباع تبدیل شوند.

## 2.3 تعادل میان طبیعت و فناوری

Eco Nojin فقط یک برند کشاورزی یا محیط‌زیستی نیست.

این اکوسیستم ترکیبی از موارد زیر است:

- علم
- فناوری
- داده
- طبیعت
- اقتصاد
- زندگی اجتماعی
- توسعه پایدار

بنابراین نباید کل هویت بصری صرفاً به سبز و قهوه‌ای محدود شود.

## 2.4 امضای طلایی

طلایی می‌تواند به‌عنوان یکی از عناصر متمایزکننده استفاده شود.

کاربردهای احتمالی:

- خطوط ظریف
- نقاط کوچک تأکیدی
- جزئیات لوگوتایپ
- مرزبندی بخش‌های ویژه
- نشانه‌های محدود در نمودارها
- جزئیات گرافیکی خاص

طلایی نباید به‌صورت گسترده در پس‌زمینه‌ها یا متن‌های کوچک استفاده شود.

## 2.5 عدم استفاده از رنگ بدون نقش مشخص

هر رنگ باید یک نقش معنایی و کاربردی داشته باشد.

استفاده از رنگ صرفاً برای زیبایی، بدون تعریف جایگاه آن در سیستم طراحی، مجاز نیست.

# 14. قواعد ترکیب رنگ و کنتراست

رنگ‌های برند به‌تنهایی برای تأیید طراحی کافی نیستند.

هر ترکیب foreground/background باید آزمون شود.

## 14.1 معیار WCAG 2.2 AA

حداقل معیارهای مورد نیاز:

| نوع محتوا | حداقل Contrast Ratio |
|---|---:|
| متن عادی | 4.5:1 |
| متن بزرگ | 3:1 |
| اجزای رابط کاربری مهم | 3:1 |
| مرز کنترل‌های ضروری | 3:1 |

متن بزرگ طبق معیار WCAG شامل متن حداقل 18pt عادی یا 14pt Bold است.

برای متن عادی، معیار 4.5:1 باید رعایت شود.

## 14.2 ترکیب‌های الزامی برای آزمون

برای هر چهار نظام رنگی باید موارد زیر بررسی شوند:

1. Primary روی زمینه اصلی
2. سفید روی Primary
3. متن اصلی روی Surface
4. Secondary روی زمینه روشن
5. Accent روی زمینه روشن
6. متن روی کارت‌های رنگی
7. متن روی Badgeها
8. متن دکمه‌های Primary
9. حالت Hover
10. حالت Focus
11. حالت Disabled
12. نمودارهای علمی
13. متن و اعداد جدول‌ها
14. لینک‌ها در متن
15. عناصر نقشه

## 14.3 محدودیت استفاده از رنگ‌های پرانرژی

رنگ‌های زیر ممکن است برای متن کوچک مناسب نباشند:

- زرد روشن
- نارنجی روشن
- سبز روشن
- فیروزه‌ای روشن
- مرجانی روشن

این رنگ‌ها می‌توانند برای پس‌زمینه‌های ملایم، نشانگرها و عناصر تزئینی استفاده شوند؛ اما متن روی آن‌ها باید با رنگ تیره و کنتراست کافی باشد.

## 14.4 رنگ و دسترس‌پذیری

در طراحی نهایی باید موارد زیر بررسی شوند:

- شبیه‌سازی انواع کوررنگی
- نمایش در grayscale
- تمایز رنگ‌های مجاور
- خوانایی در نمایشگرهای مختلف
- خوانایی در نور محیط متفاوت
- تشخیص وضعیت‌ها بدون اتکا به رنگ

رنگ تنها نباید حامل اطلاعات حیاتی باشد.

برای مثال، خطای یک عملیات باید علاوه بر رنگ قرمز، با متن یا آیکون معنایی نیز مشخص شود.

# 15. استاندارد فنی توکن‌های رنگ

### C. Component Tokens

رنگ‌های مخصوص کامپوننت:

`button.primary.background`

`button.primary.foreground`

`card.border`

`navigation.active`

`badge.warning.background`

## 15.2 فرمت‌های رنگ

در نسخه نهایی، رنگ‌ها باید حداقل در قالب‌های زیر ثبت شوند:

- HEX
- RGB
- HSL
- OKLCH

HEX برای نمایش و انتقال عمومی مناسب است.

OKLCH برای کنترل ادراکی روشنایی، اشباع و تغییرات رنگی مفید است.

## 15.3 قواعد فنی

- رنگ‌های Semantic باید مستقل از نام رنگ خام باشند.
- رنگ‌های نمودارها باید در یک مجموعه جداگانه تعریف شوند.
- استفاده مستقیم از HEX در کامپوننت‌ها باید محدود شود.
